# Agent Note: 360 防护与应用检查相同请求语义

Status: implemented

## Problem

用户提交 JSON、大请求体、重复参数和上传文件的 WAF 绕过证据，并明确目标是仓库 PHP 入口中的 360 防护。该脚本只遍历 `$_GET`、`$_POST`、Cookie 与 Referer，ThinkPHP 却能另行解析 `php://input` 中的 JSON。文件字节与被 PHP 覆盖的参数值不参与检查，旧数组拼接还有跨字段状态累积。合法用户名或密码含有 `sleep(3)` 等字面文本时，URL 编码表单被拦而 JSON 放行，正常注册结果依赖提交格式。

隔离 HTTP 复测确认：当前 PHP 版本的 20KB URL 编码表单已经被拦，危险值位于末尾的 GET/POST 重复参数也被拦；这两项与 ngx_lua_waf 的内存缓冲/首值行为不同。`?s=benign&s=/version` 只选择公开版本接口，不是 SQL 执行证据。JSON 和临时上传文件内容未检查、危险重复首值被覆盖则确实存在。

后续审查复现两项正常请求误拦：GD 生成的可识别 PNG 二维码在 IDAT 图片数据内自然包含 `<?=`，整文件 PHP 标签匹配会误判；ThinkPHP 支持 `login_ajax`、`login-ajax` 控制器名称和动作后路径参数，仅匹配原始标准 URL 会让合法注册密码在这些入口触发 SQL 正则。

## Decision

- [请求检查辅助](../../../../extend/webscan_request.php)对齐 ThinkPHP 的 Content-Type 和 `json_decode(..., true)`，递归检查每个字段的键和值，覆盖 Unicode 转义。合法 JSON 内的重复字符串成员也逐个解码检查，防止对象最后值覆盖隐藏前值。
- GET 查询串与 URL 编码请求体逐对解码并检查每次出现的值，保留应用的最后值与数组语义，不设置 8KB 扫描截断；`php://input` 由防护和框架分别读取，正常业务仍收到完整内容。
- 上传只读取 `is_uploaded_file()` 确认的 PHP 临时文件，递归覆盖多文件数组。非图片检查完整字节及 PHP 代码标记；[图片结构检查](../../../../extend/webscan_image.php)按 PNG 分块、JPEG 段/扫描区和 WebP RIFF 分块跳过二进制图像数据，只在文本元数据和尾随内容中检查 PHP 标记，不对有效图片套用 SQL 文本规则。结构损坏退回完整扫描；上传业务原有类型、2MB 上限和 Nginx 禁止执行规则继续生效。
- [360 入口](../../../../extend/360webscan.php)逐叶检查数组，停止跨字段字符串拼接；拦截页面返回 403 和 `Cache-Control: no-store`。
- 白名单与凭据例外共同使用实际路由：`?s=` 优先级与框架一致，其余沿用 PATH_INFO/REQUEST_URI/SCRIPT_NAME 回退。凭据例外按框架相同的默认应用、HTML 后缀、`Str::studly` 控制器名称和动作/路径参数语义识别目标，排除其他应用及嵌套控制器；改密按路由 `act` 覆盖 GET `act`、额外命名路径参数覆盖原动作参数的优先级，确认最终操作为 `passWord` 后才豁免。只覆盖明确的登录/注册用户名和密码、重置/改密密码字段，其他字段仍检查。凭据由验证码、输入校验、参数化用户名查询和密码哈希处理，字面 SQL/HTML 文本不能成为执行语句。
- [HTTP 回归](../../../../tests/WebscanHttpTest.php)通过 PHP 内置服务器发送真实 GET、表单、JSON、chunked 与 multipart 请求，[夹具](../../../../tests/fixtures/webscan-router.php)使用真实多应用、路由和控制器分发，覆盖登录、注册、密码重置、改密与二维码上传。数据库明确绑定内存夹具，禁用已安装应用加载，运行状态与上传保持在系统临时目录；不连接已安装站点或上游服务。

## Alternatives considered

**拒绝 JSON、大表单或所有重复参数。** 正常 API、数组/checkbox 与长配置也使用这些格式；拒绝格式无法满足正常用户不被误拦的要求。

**只扫描 JSON 原文或最后解析值。** Unicode 转义与重复键覆盖会让扫描输入与业务值不一致，必须解码并检查每次出现的字符串。

**对文件名与全部图片字节套用 SQL 黑名单。** 文件名及 PNG 文本元数据可包含字面 `sleep(3)`，与 SQL 执行无关；这种检查误伤有效图片且不能替代上传类型与禁止执行配置。

**在所有图片字节中匹配 PHP 标签。** PNG IDAT、JPEG 扫描数据和 WebP 编码数据属于二进制内容，三个字节的 `<?=` 可以自然出现，整文件扫描会误拦合法二维码。按结构只检查文本与尾随内容保留有效图片，尾随 PHP 与文本元数据 PHP 仍被拦截；不尝试把压缩图片字节解释为源码。

**只扩大 URL 正则以覆盖几个注册别名。** 仍可能漏掉框架正常接受的动作后参数和名称转换，也容易把其他应用或嵌套控制器纳入例外；应按控制器/动作语义选择凭据字段，并用真实分发回归验证。

**继续按物理路径选择白名单。** ThinkPHP 的 `?s=` 可以改变实际控制器，检查例外必须跟随最终选中的业务入口。

**删除防护或扩大整个登录/注册路由白名单。** 删除附加层超出本次范围；全路由豁免还会忽略令牌、邮箱等其他输入。仅对具体凭据字段承认其不透明数据用途。

## Consequences

JSON、表单和上传的附加检查一致，正常注册凭据与二维码图保持可用。图片结构解析不会扫描原始像素、压缩流或二进制 EXIF/ICC 元数据；上传安全继续由业务类型/大小校验与禁止脚本执行配置保障。误拦回归在修复前六项失败，修复后同组通过，78 项真实 HTTP 检查覆盖普通/渐进 JPEG、WebP、PNG 文本与二进制内容，以及控制器别名、路径参数、改密操作覆盖优先级。防护没有 IP 禁止、额外登录计数或 8KB 请求上限。它仍是正则附加层，不能以“WAF 已拦截”替代参数化查询、输出转义、权限和令牌检查，也不能把 `Token错误` 等业务响应当作数据库执行证明。宿主机另行安装的 Lua WAF 不在镜像配置范围内。
