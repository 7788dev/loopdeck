# Agent Note: 二维码上传与解码资源预算

Status: implemented

## Problem

仅限制压缩文件大小无法限制二维码解码内存：约 38 KB 的 3200×3200 PNG 就能让逐像素 PHP 数组耗尽 192 MB 内存。用户要求限制二维码上传大小，同时正常高清收款码仍须可用。

## Decision

上传上限为每张 2 MB，前端选择文件时拦截，服务端再次校验；只接受 PNG、JPEG、WebP。读取图片尺寸后、创建 GD 图像前，拒绝任一边超过 4096 像素的文件。

合规图片先合成白色背景并缩小到最长边 1024 像素，释放原始栅格后再交给二维码解码器。透明与调色板图片保留兼容性。PHP 自身拒绝大文件时也返回明确大小提示。模板通过控制器变量取得后端常量，避免模板解析命名空间时失真。

## Alternatives considered

**只限制文件字节数。** 高压缩率图片仍可展开为大栅格和昂贵的 PHP 数组。

**直接拒绝所有超过 1024 像素的图。** 会拒绝手机截图等正常高清二维码，缩放后解码可以兼顾可用性和资源上限。

**提高 PHP 内存限制。** 不限制单次输入的工作量，也无法防止多个并发请求放大资源消耗。

## Consequences

`HoneypotHttpTest.php` 在隔离 HTTP、真实防护和框架上传路径中覆盖 2 MB 边界、4096 像素边界、PNG/JPEG/WebP 及 PHP 上传拒绝；在 192 MB 下检查高清图仍能识别。前端交互回归覆盖超限不发请求及旧上传回调不能覆盖新选择。
