## 哔哩哔哩经验与大会员积分

账号详情的「今日等级经验」分别列出登录、观看、投币和大会员加成，只合计已确认的奖励。上游结算可能延迟，未确认的项目会单独标注；任务会在两小时内最多复查 24 次，每次间隔 5 分钟。

| 等级经验来源 | 每日经验 | 说明 |
| --- | ---: | --- |
| 登录 | 5 | 以每日奖励状态为准 |
| 观看 | 5 | 上报被接受后仍需确认奖励 |
| 投币 | 每枚 10，最多 50 | 依照账号保存的数量执行；配置 3 枚时目标为 30 |
| 大会员每日经验 | 10 | 需要在期大会员及符合领取条件 |

例如每天投 3 枚硬币时，以上项目全部到账可得基础经验 40，大会员另得 10。修改投币数量会消耗更多硬币，系统不会自动提高配置。

「大会员积分任务」是独立的新功能，可在账号任务列表中启停。它执行积分签到，并领取任务中心已开放的福利积分、浏览权益页及浏览装扮商城奖励。大会员积分用于兑换权益，不增加等级经验。

- 签到按账号当前活动规则执行，奖励可能随连续签到天数变化；日志显示实际回查的积分余额。
- 福利积分及两个浏览任务当前每人限一次，不是每日重复奖励。普通大会员福利为 100 积分，年度大会员为 200；已领普通福利后升级年费会员不能补领差额。
- 手机专属观看、会员购计时及消费任务不自动执行。尚需客户端领取或未开放的任务会说明原因。
- 非大会员跳过；已完成项目不重复提交。请求结果不明时保留已提交记录，按现有时限复查，未确认到账不会写成成功。

本次协议来源和验证边界见 [桌面客户端协议核查](research/bilibili-desktop-2026-11-11.md)。

## 网易云音乐人和合伙人评分

- 音乐人签到、周期/阶段任务和云豆领奖协议已按 [api-enhanced 4.40.1](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/tree/a8c781fd64faab17fedfd46e0615a2609307f163) 核对。账号资格由音乐人工作台接口判断；歌曲 ID 留空时自动查找自己的专辑歌曲，回复私信仍需配置粉丝 ID。
- 音乐人任务会检查每个子任务及奖励领取结果。子任务失败、部分领奖失败或任务列表读取失败会如实报告；没有可领取奖励属于正常情况。
- 合伙人每日评分按 [ncmp 上游协议](https://github.com/ACAne0320/ncmp/tree/0517539fa44d226a3b9cf7d6a68683f08aaa2ba3/src/core) 使用 `interface.music.163.com` 获取任务和 WEAPI 加密提交，保留原评分星数设置，评分间隔为 15–20 秒。提交后重新读取任务进度，服务端确认完成才报告成功；临时故障或进度未确认时由调度器稍后复查，已完成作品不会重复评分。
- 离线回归：`php tests/NeteaseCreatorTasksTest.php`。只读在线检查：`php tests/NeteaseCreatorLiveSmoke.php`，可通过进程环境变量 `NETEASE_MUSIC_U`、`NETEASE_CSRF` 提供会话。该检查仅读取任务；未提供账号时只能验证接口可达，实际执行和入账仍需有音乐人/合伙人资格的账号验证。

## AnyRouter 签到

- 在「VIP 功能 → AnyRouter → 添加账号」填写备注名、Cookie（含 `session`）和请求头 `new-api-user` 的数值。备注名用于区分账号，优先显示在列表和基本信息中；留空时使用站点名称或用户名。支持粘贴 Cookie 字符串或 JSON 对象；不保存账号密码。
- 代理区域只有「平台代理」和「提供代理」。平台代理自动筛选，无需选择节点；提供代理支持 `http://主机:端口`、`socks5://主机:端口` 和用户名密码认证。普通用户须填写服务器能访问的公网地址；保存后不回显 Cookie 或代理密码，留空保留原值。
- 账号列表、基本信息、任务开关、挂机时间弹窗和运行日志沿用网易云、哔哩哔哩的布局。Cookie 与代理在「更新账号」中修改，详情页展示真实用户名、余额、累计消耗、请求次数及账号分组；刷新仅查询，不签到。余额按站点返回的额度单位换算，读取失败显示暂不可用，不把旧余额当实时数据。
- 保存账号仅验证登录，不触发签到。设置每日时间并启用任务后自动运行；「申请补挂」加入统一调度队列，仍遵守任务锁、VIP 权益与冷却时间。
- 平台代理源来自 [monosans/proxy-list](https://github.com/monosans/proxy-list)，GitHub 访问受限时使用内容镜像。每次使用前显式指定代理访问 `https://anyrouter.top/api/status`，要求 HTTP 200 和有效的状态 JSON，拒绝 HTML 防护页。失败候选会被剔除，下一次从后续候选继续。
- 协议参考 [millylee/anyrouter-check-in](https://github.com/millylee/anyrouter-check-in)：同一代理 Cookie jar 获取 `acw_tc`、`cdn_sec_tc` 与 `acw_sc__v2` 后验证 `/api/user/self`，再 POST `/api/user/sign_in`。当前 ACW v2 挑战由 PHP 解析并计算，不执行服务器下发的 JavaScript，也不依赖浏览器。未知或持续防护按失败处理。
- 日志区分已签到、签到完成、Cookie 失效和网络故障。网络故障默认 5 分钟后重试，沿用 `SCHEDULER_MAX_RETRIES` 上限，耗尽后停用任务；HTTP 200、网页中的 success 字样均不代表签到成功。选择自有代理时失败不会自动切换出口。
- 公共代理有时效性，自动筛选不保证每轮都有可用节点。稳定运行可自行提供代理，或让管理员配置 `ANYROUTER_PLATFORM_PROXY`。AnyRouter 的实际领取间隔由网站决定，已签到只表示上游确认重复，不推算奖励金额。
- 离线验证：`php tests/AnyRouterClientTest.php`、`php tests/AnyRouterProxyPoolTest.php`、`php tests/AnyRouterWorkflowTest.php`。显式只读在线检查：`php tests/AnyRouterLiveSmoke.php`；检查不读取账号、不提交签到、不输出代理地址。

## 网易云每日300首说明

**网易云每日300首：已知历史去重与限时补齐**

- 网易云协议与 [NeteaseCloudMusicApiEnhanced/api-enhanced](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced) 对齐：每日任务使用 `/api/feedback/weblog` 的 `startplay`/`play` 两阶段即时上报；首次选歌使用 `/api/v1/play/record` 的 `allData`（全部记录）和 `weekData`（近一周记录）初始化历史。
- 候选歌曲排除已知历史及当天已提交的歌曲；接口返回记录与本项目上报记录按账号保存并原子写入，不再有 30,000 首截断。接口记录不能代表完整的终身听歌历史，所以最终是否新增仍以网易云累计计数为准。
- 首轮选歌保留“自定义/个性化歌单 → 多轮长尾搜索歌单 → 官方榜单兜底”。计数增加较少时，后续补批优先尝试其他搜索歌单。搜索只负责发现歌单 ID，歌曲仍从 `playlist_detail` 获取并携带真实 `sourceId`；歌曲不足 60 秒时仅在候选不足的第二轮放宽到 30 秒。
- 上报后先短暂核验（默认 15 秒），未入账时保留当天任务并默认每分钟复查；前一批等待两个核验间隔后仍有差额，再使用未提交过的歌曲补齐。已即时入账的差额也可在本次调用内补齐，核验期间不会持续占用 PHP worker。
- 首次执行起固定最多 30 分钟，且不跨自然日；进程重启和补挂不重置本轮截止时间。三种调度入口保留绝对核验时间，并预留一个调度分钟做最终读取。
- 账号详情显示已确认进度和截止时间，运行日志和每日总览只展示最终成功或失败；个人推送开启对应事件后，在最终结果确定时发送通知。
- 每天默认最多上报 6 批，批次额度在进程重启和后续调用之间共享；额度用完后仍在本轮窗口内核验已上报歌曲。实际达到目标后停止上报和重试；窗口结束仍未达到目标则记录真实差额与失败原因。
- 网络请求前先保存基线、截止时间、批次和歌曲 ID，进程中断后继续按原始基线核验，避免重复上报。读取不到有效累计数时在窗口内复查；无法保存进度时不上报并明确报告失败。
- 首批会在目标之外预留有限替换歌曲（默认目标的 20%，上限 60 首），但最终完成判断仍只看网易云累计 `listenSongs`；第三方接口限流、账号状态或异步结算异常时不能承诺绝对入账。
- 公共歌单曲目列表按歌单和曲目数量使用 6 小时共享缓存，多账号不会重复下载相同歌单；账号历史仍按账号独立过滤，不把大历史集合写入数据库查询。

常用高级配置（均会在服务端校验范围）：

| 配置项 | 默认值 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| `daka_search_rounds` | `4` | 1-8 | 长尾搜索轮数 |
| `daka_search_playlists_per_round` | `12` | 1-50 | 每轮最多读取的歌单数 |
| `daka_topup_batches` | `3` | 0-10 | 旧版兼容字段，不再控制补批 |
| `daka_max_batches_per_day` | `6` | 1-30 | 每天总上报批次上限，达到后仍核验已上报歌曲 |
| `daka_max_verification_runs` | `2` | 1-2 | 补批前等待的核验间隔数；旧版较大配置执行时按 2 次限制 |
| `daka_retry_seconds` | `60` | 60-120 | 自动核验间隔；旧配置执行时限制在此范围内，临近截止时以剩余窗口为准 |
| `daka_internal_wait_seconds` | `15` | 0-60 | 返回调度器前短暂等待累计听歌结算的秒数 |
| `daka_min_song_seconds` | `60` | 30-600 | 首轮歌曲时长下限 |

大历史账号的性能说明：历史文件按账号 SHA-256 分片，读取和过滤只发生在当前任务进程内；首次初始化只调用两次播放记录接口，后续不重复初始化。歌单详情使用进程内及共享缓存，账号删除时会同时清理对应状态文件；定时清理只匹配 LoopDeck 自己生成的状态文件，不会误删运行目录中的其他文件。

## 配额与兑换码

- 后台「注册赠送配置」设置免费赠送配额；关闭赠送或数量为 0 时，新用户初始配额为 0。
- 后台「用户数据管理」可直接设置每个用户的配额与会员时间。
- 后台「兑换码数据管理」生成配额或会员兑换码，用户在「兑换码兑换」中使用；每个兑换码只能成功兑换一次。
- 在线支付、支付回调、余额充值、余额购买和价格设置已从代码中删除。已有站点历史订单、余额及配置记录不自动删除，新安装不再创建支付订单表和余额字段。
