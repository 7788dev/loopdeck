# Agent Note: 大会员积分独立于等级经验，并按子任务核验

Status: implemented

## Problem

用户怀疑低经验来自遗漏的每日任务，要求从安装的桌面客户端核查协议。官方会员中心将「等级加速」和「大积分商城」列为不同权益：前者每日 10 等级经验，后者签到和任务所得积分用于兑换。用户明确将大会员积分作为独立新功能。

## Decision

- [VipPoints](../../../../extend/bilibili/sdk/VipPoints.php) 接入官方任务中心、签到状态、新版 JSON 签到与旧活动表单签到，只向 `bonus`、`privilege`、`dress-view` 提交已开放且可执行的任务。未知代码、手机观看/计时与消费任务不自动提交，不跟随上游任意链接。
- 工作流提交后读回签到、任务状态和余额，以已完成状态确认结果，不把返回码 0 或固定积分值当作到账。普通福利 100、年度福利 200 及浏览任务均有一次性限制，文案不许描述成每日固定收益。
- [执行器](../../../../app/service/BilibiliTaskExecutor.php) 复用既有日期与 24 × 300 秒核验机制，在任务数据中持久化 `points_submitted` 白名单列表。已提交子项只读回查，未就绪子项以后可首次提交；临时 nav、任务或签到读取失败不清空进度，明确认证失效终止核验。73319 风控拒绝终止本轮自动任务，要求用户在官方客户端完成验证。
- SDK 设备预检失败明确返回 `request_submitted=false`，不会把尚未发送的领取记入集合；真实 POST 丢失响应仍保守保留提交记录。即使集合为空，已进入当日核验的任务也保留暂时读取失败后的重试，以免设备预检恢复后永远漏签。
- [经验面板](../../../../app/service/BilibiliExperienceSummary.php) 只合计已确认的等级经验，基础、大会员及未知项目分别展示，保留投币配置与已关闭状态。会员权益纯读取不准备设备或提交领取，升级阈值缺失/非数字以及 LV6 不做错误减法。
- 新任务通过已有任务同步和账号补挂创建，不增加数据库列。旧分享与直播拒绝列表、历史保留规则不变。

## Alternatives considered

**把大积分加进今日经验。** 两者用途和账本不同，会产生虚假的升级收益。

**根据热门社区客户端恢复分享或遍历所有任务代码。** 旧页面文案不能证明奖励恢复；当前任务包含消费和手机专属操作，必须按实际证据收窄。

**根据成功 POST 立即记录奖励。** 已实际观测上游异步结算；余额变化本身也不能证明某一子任务完成。

**核验轮次完全禁止所有首次提交，或无条件重发。** 前者漏掉后来可执行的子项，后者重复请求。按任务代码持久化提交集合保留正确阶段。

**切换全部观看到桌面协议以提高经验。** 实测原有每日 3 枚硬币最终到账 50 等级经验，没有证据证明更换上报端点能提高该上限。继续使用[既有到账核验](2026-10-06-bilibili-reward-verification.md)。

## Consequences

用户得到独立积分任务及可解释的等级收益明细，不承诺隐藏的每日额外等级经验，也不自动提高投币支出。一次性奖励领完后仅有当期签到等符合条件的收益。

[协议与在线证据](../../../../docs/research/bilibili-desktop-2026-11-11.md)记录来源和局限；[积分回归](../../../../tests/BilibiliVipPointsTest.php)与[调度回归](../../../../tests/BilibiliSettlementTest.php)分别验证请求、去重和真实任务同步/调度/日志/通知。
