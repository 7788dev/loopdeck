# Agent Note: AgentRouter 首次计划当天生效

Status: implemented

## Problem

AG 账号当天凌晨绑定并设置 08:00，任务却无执行日志且下次时间是次日 08:00。调度器、账号和会员均正常；保存时间沿用通用次日计算，首次启用也跳过当天。用户要求设置后当天能自动执行。

## Decision

- [AgentRouterTaskExecutor::nextConfiguredExecution](../../../../app/service/AgentRouterTaskExecutor.php)根据持久任务状态区分首次与每日循环。未执行且无重试的任务排到当天时间及原有稳定抖动，时间已过则排到当前时间；已有执行记录使用原次日计算。
- [账号控制器](../../../../app/index/controller/Agentrouter.php)在共享任务锁内重新读取账号和 job，再保存时间或启用。[Jobs](../../../../app/index/model/Jobs.php)的创建、缺失补建、凭据恢复和共享开关按所属用户读取同一任务，使用同一计算入口。
- 有重试记录和有效执行时间时保留原 deadline，不覆盖任务选项或计数。首次 23:59 抖动跨午夜时保留已存时隙，到期后重复保存立即排队。清空时间仍关闭自动执行。
- 执行继续由统一调度器选择、claim 和比较 lease 写回；成功后正常排次日，保存设置不登录上游。登录与退出保持[原协议约束](2026-11-16-agentrouter-login-checkin.md)。

## Alternatives considered

**把所有平台的通用计算改成当天。** 其他平台的次日规则已由回归固定，用户报告的是 AG 首次计划；修改通用循环会扩大影响范围，也可能重放已执行任务。

**只替当前账号改数据库时间。** 能补跑一次，却不能修复以后新绑定、重新启用和凭据恢复的入口。

**每次保存或开关都立即签到。** 会绕过调度和任务锁，并可能重复登录、覆盖已安排的重试。首次规则以持久状态判断，保存只更新计划。

## Consequences

没有数据库结构、Compose 服务或环境变量变化。首次保存的日期现在与用户预期一致；已经执行过的每日任务仍按原循环运行，ANY 等平台默认值不变。旧安装中未执行的次日计划可通过重新保存时间修正；本次站点补排须在共享任务锁内核对原计划并只修改未执行的目标任务。

[AgentRouterScheduleTest](../../../../tests/AgentRouterScheduleTest.php)用隔离数据库重放首次保存、已过时间、重复保存、跨午夜、重试、开关与恢复，并实际执行统一调度器及伪 HTTP 登录/余额/退出全流程；完成后的旧选择不能再次发出登录请求。
