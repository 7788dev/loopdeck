# Agent Note: 账号绑定互斥与删除事务

Status: implemented

## Problem

控制器在保存前检查平台账号归属，但不同用户锁的是不同用户行，数据库唯一索引也包含 uid。两个绑定请求在检查后同时进入保存，会创建两个所有者。真实 MySQL 双进程、两轮各三次复现均出现两个所有者。用户侧删除账号则先删除凭据再清理任务；清理失败后无法重试恢复完整状态。

按完整外部账号名生成永久锁文件时，无配额用户也能通过不同收款识别码不断创建文件，绑定失败不能限制磁盘消耗。

## Decision

`Accounts::saveAccount()` 将平台和外部账号 ID 的 SHA-256 前两个十六进制字符映射到 256 个固定安装共享锁，持锁直到用户行锁事务提交；事务内再次检查已有所有者。同一账号在所有用户间始终使用同一把锁，账号总配额仍由用户行锁保证。

网易云、哔哩哔哩用户删除入口复用管理模型的事务清理，并显式传入当前 uid。账号、任务和最后一个所有者的日志一起提交，网易云状态文件在提交成功后清理；历史重复所有者仍有账号时保留共用日志。

## Alternatives considered

**只保留控制器预检查。** 无法串行不同用户的并发请求。

**把唯一索引改为全局平台账号。** 会使存在历史重复所有者的安装迁移失败，需要先决定历史数据归属；当前没有自动合并或删除历史账号的授权。

**部分删除后返回失败，让用户重试。** 凭据行已消失时重试无法再定位完整清理对象，也不能恢复被删数据。

**每个输入单独留一份锁文件。** 即使配额检查拒绝保存，攻击者仍能耗尽文件数量；固定锁池只让极少数哈希碰撞的并发绑定提示重试。

**释放锁后删除文件。** 等待者可能仍持有旧 inode，新请求却打开新文件，导致同名账号同时持有两把互不相干的锁。

## Consequences

不改账号唯一索引，不删除历史重复记录。此互斥要求单安装共享锁目录。离线回归覆盖回滚、跨用户拒绝和共用日志；显式 MySQL 集成测试覆盖两个用户同时绑定同一账号。

既有锁文件不在线删除。`AccountBindingResourceTest.php` 通过 768 次实际配额拒绝检查固定文件上限，并验证持锁拒绝、释放恢复和跨用户唯一归属。
