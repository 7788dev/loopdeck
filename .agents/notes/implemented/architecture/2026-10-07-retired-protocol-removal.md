# Agent Note: 删除小黑盒和已停用协议实现

Status: implemented

## Problem

小黑盒仍保留导入会话、签到、页面和调度入口；哔哩哔哩旧直播任务已拒绝调度，但适配器和 SDK 仍有可调用的旧协议。用户明确要求删除小黑盒及其他停用平台、未使用的旧协议。

## Decision

- 删除小黑盒 SDK、签名实现、cron 控制器、用户页面、导入与账号操作逻辑、FAQ 和新装任务种子；统一调度白名单移除小黑盒。
- 删除哔哩哔哩旧礼包、心跳、应援团、心跳礼物、直播签到、主站分享及全局房间配置的适配器和 SDK 方法，并清除新装种子与旧分享的自动补种。
- 保留哔哩哔哩六项有效任务及其真正使用的依赖。停用名称只保留在拒绝列表、历史展示和迁移清理中；小黑盒旧任务由全局维护停用，历史数据库记录不删除。
- 用户自动路由保留一行 404 守卫，显式路由改成退役映射。爱奇艺、贴吧、米哈游、运动和抖音没有剩余的已跟踪平台实现；其不可达约束继续保留。
- 删除对应的旧协议成功测试，在 `FeatureRemovalTest.php` 断言文件、方法与入口均不再可用；通用数据隔离测试可继续使用历史平台类型作为数据样本。

## Alternatives considered

**只隐藏导航或只禁用执行。** 实现继续留在源码，容易被新入口误接回去，未完成用户要求的删除。

**删除历史数据和全部拒绝映射。** 历史数据不属于协议代码；移除自动路由守卫又会把旧 URL 变成框架回退入口，失去明确的不可达保证。

## Consequences

旧入口返回 404，安装不再生成退役任务。历史日志仍可供管理员查阅；Composer 构建重新生成 classmap，删除的类不再出现在新镜像的可加载实现中。
