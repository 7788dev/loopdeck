# 2026-09 维护与通知改造记录

- 检查并修复任务调度、通知、权限、请求校验、前端和数据库访问中的已证实问题。
- 保留网易云每天按账号和日期计算的 3–15 分钟偏移，前台说明设置时间与实际执行时间的区别。

- 支持任务成功、最终失败、账号失效、会员到期、Epic 周免提醒和每日任务总览；总览默认 22:00，可修改。

- 提供通知去重、投递重试、凭据保护、个人设置隔离，以及旧 Bark 设置兼容。
- 完成离线回归、数据库/接口集成和前端实际渲染验证，再推送 GitHub、等待镜像构建并更新服务器。

## 已确认的检查结论

| 范围 | 证据与处理方向 |
| --- | --- |
| 网易云计数 | 旧逻辑把延迟入账误记为失败；前一轮热修复已在本工作区，需一并正式发布。 |
| 随机偏移 | `NeteaseSchedule::dailyOffset` 包含账号与日期，范围 180–900 秒；下一次的具体时间不代表每天固定。 |
| 其他平台偏移 | 原先按任务 ID 固定计算；改为按账号和计划日期计算，并统一 HTTP、CLI 和个人设置中的时间计算。 |
| 通知设置 | 旧页面只有 Bark Token，由后台总开关控制，未集成到个人中心，也没有事件与汇总配置。 |
| Epic 调度 | 容器只请求统一调度器，该调度器只选择网易云和哔哩哔哩；Epic 周免和小黑盒任务没有接入。 |
| Epic 投递 | 邮件发送返回 false 被忽略，任务仍可推进到下周；旧周五/周末计算可能额外跳过一周。 |
| 请求校验 | `CheckAjaxRequest` 依赖 `isAjax()`，框架允许请求参数 `_ajax` 模拟 AJAX，且未校验来源。 |
| 调度入口 | 服务器只读验证 `/cron/common/statusTag` 无密钥也返回 200；增加整个 cron 应用鉴权与强制路由白名单，阻断公共辅助方法被当成 HTTP 操作。 |
| 登录状态 | 登录中间件未重新拒绝已封禁账号或错误站点，每请求重复读取用户且反复写入已清空的会员字段。 |
| 前端输出 | 多个 DataTables 文本列直接渲染数据；SMTP 密码以明文输入并回填；Epic 文案把提醒误写成自动领取。 |
| 通知响应 | Bark 把没有合法业务响应码的 HTTP 200 也视为成功；现有投递同步占用执行任务的请求。 |
