# LoopDeck

LoopDeck 是基于 One Tool（2022）二次开发的一套开源云任务系统，支持网易云音乐、哔哩哔哩等平台的等级与日常任务。

项目已移除原作者失效的旧协议与加密文件，并对任务调度、平台协议、容器部署、日志和更新流程进行了持续重构。

## 当前版本

### v1.1.25（2026-09-04）

**哔哩哔哩每日分享下架与容器自动更新**

- 哔哩哔哩“每日分享”（`shareaid`）已标记为“已下架”，调度器会停用历史 job；每日经验任务不再调用分享接口，保留登录、观看、投币和经验日志核验。
- 更新器改为独立的定时容器：并行探测多个版本源和镜像代理，选择最高版本中的较快路线，校验镜像版本标签并在健康检查失败时自动回滚。后台仅展示状态，不再提供手动更新入口。
- 网易云每日300首协议继续与 [NeteaseCloudMusicApiEnhanced/api-enhanced](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced) 对齐。

### v1.1.24（2026-09-04）

**网易云每日300首：终身未听硬过滤与有限自适应补批**

- 网易云协议与 [NeteaseCloudMusicApiEnhanced/api-enhanced](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced) 对齐：每日任务使用 `/api/feedback/weblog` 的 `startplay`/`play` 两阶段即时上报；首次选歌使用 `/api/v1/play/record` 的 `allData`（全部记录）和 `weekData`（近一周记录）初始化历史。
- 候选歌曲只接受账号历史中没有出现过的歌曲；历史记录以及本项目成功上报的歌曲保存到 `runtime/netease-daka/` 的账号哈希文件中，状态写入采用原子替换，不再有 30,000 首截断。接口返回的历史会在首次运行时加入硬过滤，之后每次成功上报继续追加。
- 选歌顺序调整为“自定义/个性化歌单 → 多轮长尾搜索歌单 → 官方榜单兜底”。搜索只负责发现歌单 ID，歌曲仍从 `playlist_detail` 获取并携带真实 `sourceId`；歌曲不足 60 秒时仅在候选不足的第二轮放宽到 30 秒。
- 每天先提交当前差额，网易云累计听歌数可能异步结算或部分计数时，默认允许最多 3 个有限补批（首次批次之外），每天最多 6 个批次；连续 3 轮没有累计增量后停止。将 `daka_topup_batches` 设为 `0` 可恢复“首批后只核验”的保守模式。
- 公共歌单曲目列表按歌单和曲目数量使用 6 小时共享缓存，多账号不会重复下载相同歌单；账号历史仍按账号独立过滤，不把大历史集合写入数据库查询。

常用高级配置（均会在服务端校验范围）：

| 配置项 | 默认值 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| `daka_search_rounds` | `4` | 1-8 | 长尾搜索轮数 |
| `daka_search_playlists_per_round` | `12` | 1-50 | 每轮最多读取的歌单数 |
| `daka_topup_batches` | `3` | 0-10 | 首批之后允许的补批次数 |
| `daka_max_batches_per_day` | `6` | 1-30 | 每日批次安全上限 |
| `daka_max_verification_runs` | `3` | 1-10 | 无累计增量时的核验上限 |
| `daka_retry_seconds` | `900` | 120-3600 | 候选不足或异步结算时的重试间隔 |
| `daka_min_song_seconds` | `60` | 30-600 | 首轮歌曲时长下限 |

大历史账号的性能说明：历史文件按账号 SHA-256 分片，读取和过滤只发生在当前任务进程内；首次初始化只调用两次播放记录接口，后续不重复初始化。歌单详情使用进程内及共享缓存，账号删除时会同时清理对应状态文件；定时清理只匹配 LoopDeck 自己生成的状态文件，不会误删运行目录中的其他文件。
