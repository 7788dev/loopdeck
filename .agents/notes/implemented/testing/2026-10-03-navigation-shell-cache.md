# Agent Note: 侧栏回归必须覆盖用户与后台入口及脚本缓存

Status: implemented

## Problem

原版共享脚本在每次 PJAX 完成后无条件关闭侧栏。v1.2.18 修正了桌面端逻辑，却只直接执行共享脚本做回归，没有检查站长后台实际渲染的脚本引用。原版后台仍引用不带版本号的 `app.min.js`，生产服务器对此资源设置 86400 秒缓存，已缓存旧脚本的浏览器可能继续执行旧逻辑。用户再次报告后台仍会收起侧栏。

## Decision

- 桌面端的 PJAX 导航保留侧栏当前状态，不主动关闭，也不强行展开；当前若依桌面断点为 768px。小屏侧栏覆盖内容，导航完成后收起。
- 用户前台、站长后台的若依页面入口都必须接受验证；原版已按[单模板决策](../architecture/2026-10-03-ruoyi-only.md)移除。共享脚本行为测试检查连续导航、初始展开/收起及断点边界；渲染测试检查两套壳层实际 HTML 中脚本存在、仅加载一次且版本参数等于当前 `VERSION`。
- 所有页面引用 `/static/js/app.min.js` 时都附加 `?v={:app_version()}`，包括登录页面和安装页面，避免相同旧缓存入口遗漏。版本更新后普通页面刷新即可请求新脚本。

手机首次点击子菜单时，触屏保留的 `:hover` 命中桌面折叠侧栏规则，子菜单和标签被设成 absolute 并右移 70px。手机样式现在在 `#side-menu` 下显式恢复二/三级菜单与标签的普通流位置，覆盖 hover 的 left/top、最小宽度、背景和滚动容器；所有不含 in 的闭合项都不因 hover 再显示，不依赖 collapse 标记是否存在。当前路由高亮展开祖先菜单时先移除 collapse，避免同时含 in/collapse 的菜单第一次关闭后丢失两个标记。手机断点使用 767.98px，覆盖浏览器缩放导致的 767.x 小数宽度空档，768px 起显式显示桌面侧栏，避免上游 max-width:768px 规则在边界将其隐藏；桌面悬浮菜单保留。

浏览器回归使用 [MobileSidebarBrowserCheck.js](../../../../tests/MobileSidebarBrowserCheck.js) 的只读断言：通过浏览器工具加载文件里的函数，在实际页面点击每组菜单后执行。检查首次展开、关闭、重开与切换兄弟菜单；覆盖用户端网易云/哔哩哔哩/收款码、后台设置/任务/数据菜单的 390px 和 767px 布局，并检查桌面折叠状态。断言验证实际 computed style 与菜单边界，不只比较样式文本。

## Alternatives considered

**只修脚本，再要求用户强制清缓存。** 服务端文件更新不能让已有的无版本 URL 缓存自动失效，下一次发布仍会复发。

**只测试脚本函数。** 可以证明当前源码正确，但不能证明后台 HTML 会加载它；必须同时检查渲染后的资源入口。

**禁用全站静态资源缓存。** 为一个可变业务脚本牺牲全部资源的缓存效率，没有必要。

**导航后总是展开侧栏。** 会覆盖用户主动收起的选择，且在小屏遮挡内容。

**点击后主动移除焦点或禁用所有 hover。** 无法可靠消除触屏的悬浮状态，还会损害键盘焦点与桌面操作；按视口隔离桌面浮层样式。

## Consequences

发布侧栏或共享前端修复时，检查用户前台与站长后台，不能以用户前台通过代替后台验收。保持发布版本号更新，并保留可定位到失败页面的资源版本断言。此记录补充 v1.2.18 侧栏修复遗漏的项目记忆，不改写既有 Git 提交。
