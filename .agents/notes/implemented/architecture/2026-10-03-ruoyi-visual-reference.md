# Agent Note: 若依视觉迁移的最新版对照

Status: implemented

## Problem

用户反馈迁移后的若依组件比例、配色和层级不协调，并要求先分析官方最新版。上一轮仅引入基础样式，混入旧模板网格和大块彩色组件，不能据此认为视觉迁移完成。

## Decision

2026-10-03 查询官方 GitHub 标签与主分支：

- [经典版 v4.8.3](https://github.com/yangzongzhuan/RuoYi/tree/v4.8.3)，主分支提交 `7995a83e04e1a88aaea5a8a7c50570dffcb145e0`（2026-09-07）。重新下载此提交的 `skins.css`、`style.min.css`，与当前资源哈希一致；问题重点在迁移组合方式，不是这两份资源过旧。
- [Vue3 v3.9.2](https://github.com/yangzongzhuan/RuoYi-Vue3/tree/v3.9.2)，主分支提交 `838965c5a18d2c61b73ec30c6e288057aaa08b63`（2026-08-26）。已读取 `variables.module.scss`、`settings.js` 和 `Navbar.vue`：默认白色 50px 顶栏、200px 深色侧栏、分层文字及卡片页签。

两种视觉路线已向用户询问；在未收到进一步限定时，按已告知的 Vue3 视觉方向实施，保留 PHP 与 Bootstrap 3 的业务交互基础。白色 50px 顶栏、200px 深色侧栏、浅灰内容区和轻量卡片承担界面层级。统一 14px 正文、34px 常规输入框、40px 认证输入框，统计与快捷入口使用浅色卡片，强调色集中在操作、选中状态和小图标。

正文采用 `#303133`，辅助文字采用 `#606b78`，主按钮使用较收敛的 `#337ab7`；不通过降低整页透明度来调色。登录背景取自上述 Vue3 提交并保留许可，未引入示例菜单或示例业务数据。首页、认证页、后台和用户页共享带 `app_version()` 的样式资源。

最终逐页对比还移除了兑换页和账号卡片的遗留彩色表头，统一了各平台头像区域与状态标签。高饱和背景不承担普通栏目标题的区分，状态标签使用浅底色和深色文字，兑换输入框与操作按钮对齐。

内容页仍使用 PJAX。侧栏当前高亮在导航时重置后再定位，桌面展开/收起偏好保持不变；移动二级菜单、右侧用户下拉菜单及折叠 Logo 分别处理尺寸边界。页脚位于滚动内容区之外，避免负边距造成横向溢出。

## Alternatives considered

**仅更新第三方 CSS。** 已验证两份核心 CSS 与最新主分支一致，无法解决布局和组件组合问题。

**整页统一加暗色遮罩或降低透明度。** 会同时降低文字对比度，不能改善组件层级和间距。

**把视觉优化扩展为 Vue / Java 技术栈替换。** 当前需求是优化整体模板；可参考 Vue3 的视觉语言，但业务后端、原版切换及现有交互需要保留。

## Consequences

- 两套模板仍共享原有业务接口；这次改变视觉与导航高亮，不是引入 Vue / Java 技术栈。
- 渲染回归检查自定义样式的版本参数；交互回归增加旧菜单高亮清理，保留原版和若依的侧栏断点检查。
- 桌面收集 46 个若依页面/状态的截图并检查横向溢出；实际检查首页、认证、账号详情、后台表格、弹窗与手机菜单，避免仅凭模板编译通过断言视觉正确。

官方经典版把内容放进 iframe，本项目使用 PJAX。直接给顶层添加主题类会让 `.skin-blue .wrapper` 等选择器影响业务内容，因此自定义样式显式隔离内容背景，不能机械复制壳层类名。后续视觉修改沿用这份来源与分层约束，不把框架升级、皮肤选择和业务模板混为一谈。
