# Agent Note: 付费权益与完成状态原子提交

Status: implemented

## Problem

余额购买先扣款、支付回调先完成订单、卡密先标记已用，再发放权益。任一后续写入失败会让用户付出成本但没有得到权益；回调重试还可能被“订单已处理”挡住。

## Decision

[支付回调](../../../../app/service/PaymentSettlement.php)在事务内锁定订单、检查状态、锁定用户并发放、写财务记录、完成订单。失败回滚后原订单仍可重试；重复已完成回调不再发放。验签直接针对传入的回调内容。

[余额购买](../../../../app/index/model/Pays.php)和[卡密兑换](../../../../app/index/model/Kms.php)在同一事务锁定用户后扣费或兑换并发放，避免同一用户并行续费覆盖到期时间。密码重置也把令牌消费与密码写入放在同一事务。

## Alternatives considered

**手动补余额或重置订单状态。** 中间异常、进程退出和并发请求使补偿本身也可能失败。

**回调失败后由站长永久手工处理。** 可以保留历史异常订单人工核对，但不适合继续制造新的不可重试状态。

## Consequences

需要事务存储引擎；现有安装表使用 InnoDB。没有数据库结构迁移。历史已标完成但未发放的订单不自动补发，以免重复发放，需核对财务历史。[测试](../../../../tests/PaymentWorkflowTest.php)覆盖异常回滚与重放。
