# Agent Note: 登录任务日志的等级进度装饰永不降级登录成功

Status: implemented

## Problem

用户希望「每日登录」任务的成功日志(`login_work`)在「登录成功」后追加距下一级还差的登录天数(如 `登录成功，3天后升级`)。等级读取是登录成功之后的第二次上游请求,若这次请求失败(传输异常、非 200、字段缺失),不能让一个已经成功的登录被记成失败或触发分钟级重试——那会白白烧掉重试预算,并让用户误以为登录任务坏了。

## Decision

- `login_work()` 成功路径拼接 `loginLevelSuffix()` 装饰:剩余天数 = `nextLoginCount - nowLoginCount`(与控制台 `loginnum` 同口径,`app/index/controller/Console.php`)。
- 装饰是 best-effort:`level()` 抛异常、非 200、缺 `data`、任一登录计数缺失或无效、剩余天数 ≤ 0(含满级)一律回退纯「登录成功」,整体 code 恒为 200,不设 `cookiezt`。计数只接受非负整数及其字符串形式,明确保留真实的 0;不把缺失字段当成 0。
- 登出/失效判定仍以 `getInfo` 为唯一权威,装饰读取不参与 `cookiezt` 判定。

## Alternatives considered

- **等级读取失败时整体报 201/重试**:输在把装饰性读取当成了任务本体,登录明明成功却进入重试循环,最终可能烧穿重试预算记成 `[失败]`。
- **在调度器/控制器侧二次查询等级拼接文案**:输在把平台协议细节泄漏进调度层,违反适配器封装,且同一个上游端点会被两处调用。
- **满级/无登录天数要求时输出「0天后升级」**:输在文案失真——0 天不等于马上升级(可能只差听歌量),如实回退纯文案更诚实。
- **缺失登录计数时默认按 0 计算**:输在把未知进度当作已知事实。`nowLoginCount` 缺失且 `nextLoginCount=800` 时会误报「800天后升级」,因此两个计数都须通过校验后才计算。

## Consequences

- 回归覆盖:`tests/NeteaseLoginLevelSuffixTest.php`(成功追加、真实零计数及整数字符串、零天数回退、缺失/null/非整数/负数计数、缺数据/非 200/抛异常回退)+ `tests/NeteaseWorkflowTest.php` 传输桩含 `/weapi/user/level` 形态断言(注意 weapi 请求的实际 URL 前缀是 `/weapi/`,不是 `/api/`)。缺失计数回归在修复前失败、修复后通过。
- 文案承诺「X天后升级」隐含"每天登录"假设;若未来文案要求区分听歌量瓶颈,需在此 note 基础上扩展,而不是改判定口径。
