# Agent Note: 兑换权益与完成状态共同提交

Status: implemented

## Problem

兑换码先标记已用，再发放权益，后续写入失败可能消耗兑换码却没有增加配额。并行续期也可能覆盖会员到期时间。

## Decision

[兑换码兑换](../../../../app/index/model/Kms.php)在事务内锁定用户，条件领取兑换码后发放权益，失败时恢复兑换码可用状态，成功后刷新用户会话。密码重置也把令牌消费与密码写入放在同一事务。

此前的支付回调、余额购买与结算代码已按[移除在线支付的决定](2026-09-28-admin-managed-entitlements.md)删除，事务规则只适用于保留的流程。

## Alternatives considered

**完全独立写入兑换码与用户权益。** 并发兑换和中途异常可能造成重复发放或权益丢失。

**失败后让管理员永久手工处理。** 不能替代可重试的兑换流程。

## Consequences

事务依赖 InnoDB 等事务引擎。首次安装的兑换码表明确采用 InnoDB；旧库不自动迁移，不能仅凭 SQLite 回归声称旧 MyISAM 表具备事务保证。[运行测试](../../../../tests/QuotaWorkflowTest.php)覆盖发放失败、恢复、重试、重复兑换与跨用户重放。
