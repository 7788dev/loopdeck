# LoopDeck 系统分析与修复验收

本轮基于 v1.2.34（`9612b3a`）及当时工作区内容，检查用户、管理、Cron、CLI、安装入口，共享服务、平台适配、模板脚本、数据库、容器和更新流程。确认并修复 **8 类问题**。每类结论均经过第二轮复核；可执行的问题保留了修复前失败、修复后通过的证据。

主要业务修复在 `0ede346`；后续提交补齐服务器 HTTP 验收与测试环境隔离。工作区已有的可信代理 IP、异常响应边界和闲置方法清理也经过回归后纳入本次交付。

## 确认的问题与处理

### 1. P1：迟到的会员到期处理会撤销已经完成的续期

调度批次缓存旧的过期日期后，用户兑换续期；旧处理仍无条件清空会员日期并停用任务。复现中已续期到 `2099-12-31` 的会员被清空。

[Users::pauseExpiredVipJobs](../app/index/model/Users.php) 在兑换共用的用户行锁内重新读取有效期，并在同一事务中处理过期权益和会员任务。统一调度、平台 Cron、CLI、Epic 均使用这个结果；登录中间件的条件写入落空后也重读用户。

验证：[StateConsistencyTest.php](../tests/StateConsistencyTest.php) 覆盖缓存后续期、旧入口再次检查、续期后继续执行和重复到期只发送一次通知。

### 2. P1：任务配置保存与执行回写互相覆盖，且会丢失核验进度

运行中保存配置原来返回成功，但旧任务随后把旧配置写回。即使保存发生在任务领取之前，批次中预先选出的旧行也会覆盖新值。普通保存还会删除哔哩哔哩的已提交领取标记、核验次数和调度失败次数；Epic 偏好保存同样重置失败预算。

[Jobs::saveUserConfig](../app/index/model/Jobs.php) 仅在取得任务锁后保存，保留调度器拥有的元数据；各执行入口领取后重读任务。Epic 偏好保存同样保留进度，并拒绝改写运行中的任务。

验证：运行中保存被拒绝且原值保留，释放后保存成功；领取前已保存的新值不再丢失；待核验标记和重试次数保持不变。

### 3. P2：用户删除账号缺少完整事务，失败后留下残缺数据

网易云和哔哩哔哩用户入口先删凭据再清理任务、日志。注入任务删除失败后，原实现已经丢失账号或历史，用户无法用同一个操作恢复完整状态。

两个入口复用[账号事务清理](../app/admin/model/Accounts.php)，显式限制当前用户。数据库清理全部提交后才删除网易云状态文件；仍存在历史重复所有者时保留共享日志。

验证：失败后账号、任务、日志全部保留，状态文件不被提前删除；重试成功后完整清理；跨用户删除被拒绝。

### 4. P2：CLI 的账号状态边界与其他调度入口不一致

网易云 CLI 会执行 `state=0` 的账号；哔哩哔哩 CLI 在处理已失效账号时，会把用户手动暂停的任务也改成 `-1`，导致重新登录后被恢复。

网易云 CLI 增加账号状态检查；哔哩哔哩只处理启用中的任务，并对当前任务保留租约写回检查。

验证：失效网易云账号的适配器调用次数为零；哔哩哔哩手动暂停任务始终保持暂停。初筛时对“所有账号失效分支都会恢复暂停任务”的怀疑已撤回：其他公共分支原本就有 `state=1` 限制。

### 5. P2：通知租约到期后可重复领取，迟到结果可覆盖新状态

原通知领取只延后 120 秒，发送进程仍存活时也可被另一发送者重新领取；完成写回只按 ID 更新。复现中第二个发送者取得同一消息，旧发送者又把取消状态覆盖为成功。

[NotificationRepository](../app/service/NotificationRepository.php) 持有安装共享锁，并在完成时比较状态、租约时间和尝试次数；正常、异常及析构路径均释放自己拥有的锁。

验证：[NotificationLeaseTest.php](../tests/NotificationLeaseTest.php) 与真实通知数据库集成均通过。

### 6. P2：验证码表不能保存合法长邮箱和 IPv6 地址

原 `captcha.send`、`captcha.ip` 都只有 20 个字符。真实 MySQL 严格模式下，长邮箱、完整 IPv6 分别触发写入异常，影响密码找回等依赖该表的流程。

新安装分别使用 255、45 个字符；[SchemaMaintenance](../app/service/SchemaMaintenance.php) 为旧库扩容，跳过已经更宽的自定义列。新版维护标记使新增迁移不必等待旧的每日标记过期。

验证：[RecoveryDatabaseIntegration.php](../tests/RecoveryDatabaseIntegration.php) 的短邮箱对照、长邮箱、IPv6、旧列升级后写入全部通过。该变更涉及数据库结构，发布前已验证备份可恢复。

### 7. P2：两个用户可并发绑定同一个平台账号

控制器检查发生在事务之前，不同用户锁的是不同用户行，现有唯一键也包含 uid。两轮真实 MySQL 测试各重复三次，原实现每次都产生两个所有者。

[Accounts::saveAccount](../app/index/model/Accounts.php) 按平台与外部账号 ID 持有共享锁，事务内重新检查归属，仍使用用户行锁保证总配额。不变更历史唯一键，不自动删除历史重复记录。

验证：[AccountBindingDatabaseIntegration.php](../tests/AccountBindingDatabaseIntegration.php) 修复后连续三轮均只有一个所有者。

### 8. P1：标为离线的结构测试会修改已配置数据库

原 `SchemaMaintenanceTest` 初始化安装应用后直接运行维护。在测试容器中删除一个索引，再运行原测试，两轮都实际重建了配置所指数据库中的索引。这说明异常捕获不能提供测试隔离。

该测试改用内存数据库，断言 PDO 驱动为 SQLite。真实 MySQL 检查只在显式指定的空 `loopdeck_qa_*` 数据库中进行。

验证：重放相同操作，两轮测试均未改变配置数据库。另修正更新器测试对宿主环境开关的隐式依赖；关闭更新时业务正确返回“已禁用”，因此相关初次测试失败没有被列为更新器缺陷。

## 验收结果

- Windows：68 个 PHP 离线测试及前端交互测试全部通过；162 个应用及适配层 PHP 文件语法检查通过。
- Linux 隔离容器：PHP 8.2.32 下 68 个 PHP 离线测试和 Node 交互测试通过。
- 真实 MySQL：恢复字段升级、并发绑定、通知及 Epic、网易云最终结果的集成脚本通过；网易云覆盖三种调度入口、核验间隔、异常、最终投递和去重。
- 实际 HTTP：21 项断言通过，包括登录、两套后台、分页、敏感字段隐藏、请求来源校验、资料编码、Cron 鉴权、不可路由的辅助方法、退役入口及上传目录 PHP 拦截。
- 备份：数据库快照在独立 MySQL 中恢复成功，表数与源库一致；数据卷归档可读取，保留配置和持久数据。

HTTP 用例校准了基础镜像的健康响应、页面实际使用的大小写路由、JSON Accept 头和合法表单输入。由这些用例差异产生的失败已排除，没有据此修改业务行为。

服务器测试使用独立容器、内网和数据卷。平台上游采用可控 fixture，没有使用生产账号验证真实第三方奖励到账；本报告的通过结论限于已执行的项目逻辑和部署验证。
