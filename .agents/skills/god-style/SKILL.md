# GOD 风格

GOD 是一套视觉与交互基座：白色顶栏、深色侧栏、浅灰画布、紧凑白卡片、克制蓝色操作与清晰中文排版。保留用户认可的舒适比例和信息密度，根据新产品调整内容、布局和组件，不把任何既有业务系统直接复制成新网站。

## 使用流程

1. 从当前请求和项目确定页面、用户角色及技术栈；已明确的需求直接实施。GOD 决定视觉，不决定后端、路由、权限、数据模型或部署方式。
2. 阅读 [设计规范](references/design.md)，查看其中与任务对应的基准截图。先确定壳层、间距、字号、表单与卡片层级，再安排业务内容。
3. 以 [god.css](assets/god.css) 的 `:root` 变量作为默认配置。无框架项目可以复制其组件样式；现有 React、Vue、PHP 等项目将变量和布局映射到已有组件体系，避免为套风格引入第二个框架或全局覆盖库。
4. 根据页面选取最接近的骨架：[控制台/后台](assets/dashboard.html)、[公开首页](assets/home.html)、[登录注册](assets/auth.html)。骨架是无业务的布局起点，替换产品名、路由、字段和内容，接入真实业务；没有数据时使用明确空态，不能把示例当作实际统计。
5. 允许按后续需求二次创新。默认保留结构比例、文字对比度、低饱和层级和主要交互约定；品牌色、首页内容、密度和导航形式可以有依据地调整。前台和后台共用同一套视觉变量。
6. 在桌面和手机检查真实页面：导航、表单、表格、弹窗、空态、加载、错误和禁用状态。检查横向溢出、文字对比、菜单遮挡、焦点可见及桌面侧栏状态；为改动后的关键页面截图，核对与基准的偏差是否有需求依据。

## 文案与边界

- 产品 UI 使用产品名称和用户能理解的业务术语。不在页头、页脚、登录页、帮助文案或提示中写“GOD 风格”“若依”“RuoYi”“原版”、框架名或“本系统采用某框架”；用户明确要求展示品牌/技术说明时再按请求处理。
- 使用说明只讲用户怎么操作、会得到什么结果。后台特殊数值、存储标记、兼容机制和内部合并规则放在技术资料或管理员说明，不混入普通用户页面；实际安全仍由服务端授权和校验保障。
- 不添加上游演示菜单、测试账号、无关图表、随机统计或装饰性功能。不复制 LoopDeck 的账号、任务、兑换等业务到不相关产品。
- 不自动把此技能安装到全局，不创建任务、不推送、不部署；那些操作需要当前任务的授权。
- 来源和许可只在内部资料及资源许可文件保留，不能因去掉 UI 框架宣传而删除必要的版权声明。复用上游文件前读 [来源与复用](references/provenance.md)。

本目录自包含，可以整目录移动到其他项目或全局技能目录。宿主需发现并加载技能后，才能根据自然语言“使用 GOD 风格”选择它；无需把当前项目绝对路径写入新项目。
