# Agent Note: 侧栏回归必须覆盖四套页面入口和脚本缓存

Status: implemented

## Problem

原版共享脚本在每次 PJAX 完成后无条件关闭侧栏。v1.2.18 修正了桌面端逻辑，却只直接执行共享脚本做回归，没有检查站长后台实际渲染的脚本引用。原版后台仍引用不带版本号的 `app.min.js`，生产服务器对此资源设置 86400 秒缓存，已缓存旧脚本的浏览器可能继续执行旧逻辑。用户再次报告后台仍会收起侧栏。

## Decision

- 桌面端的 PJAX 导航保留侧栏当前状态，不主动关闭，也不强行展开；原版桌面断点为 992px，若依为 768px。小屏侧栏覆盖内容，导航完成后收起。
- 用户前台、站长后台的原版和若依四套页面入口都必须接受验证。共享脚本行为测试检查连续导航、初始展开/收起及断点边界；渲染测试检查四套实际 HTML 中脚本存在、仅加载一次且版本参数等于当前 `VERSION`。
- 所有页面引用 `/static/js/app.min.js` 时都附加 `?v={:app_version()}`，包括登录子模板和安装页面，避免相同旧缓存入口遗漏。版本更新后普通页面刷新即可请求新脚本。

## Alternatives considered

**只修脚本，再要求用户强制清缓存。** 服务端文件更新不能让已有的无版本 URL 缓存自动失效，下一次发布仍会复发。

**只测试脚本函数。** 可以证明当前源码正确，但不能证明后台 HTML 会加载它；必须同时检查渲染后的资源入口。

**禁用全站静态资源缓存。** 为一个可变业务脚本牺牲全部资源的缓存效率，没有必要。

**导航后总是展开侧栏。** 会覆盖用户主动收起的选择，且在小屏遮挡内容。

## Consequences

发布侧栏或共享前端修复时，检查用户前台与站长后台的两套模板，不能以用户前台通过代替后台验收。保持发布版本号更新，并保留可定位到失败页面的资源版本断言。此记录补充 v1.2.18 侧栏修复遗漏的项目记忆，不改写既有 Git 提交。
