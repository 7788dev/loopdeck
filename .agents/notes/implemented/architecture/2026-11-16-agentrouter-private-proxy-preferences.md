# Agent Note: AgentRouter 私有平台代理与成功节点记录

Status: implemented

## Problem

服务器直连受验证与连接重置阻断，订阅节点需要转换后才能访问 AG。早期全站环境出口不能让站长在后台管理，也会忽略用户的自有代理选择。用户要求平台来源归站长、地址不暴露给项目使用者，并记住最多三条成功节点：先复用第一条，首次失败保留，下一次执行日仍失败才移除并尝试后面的节点。

## Decision

- [AgentRouterProxySettings](../../../../app/service/AgentRouterProxySettings.php) 在既有 `configs` 表保存两个 `agentrouter_private.*` JSON 记录，分别持有来源/官方域名与节点状态。共享 `sys` 加载忽略该前缀；普通配置写入拒绝该前缀（含大小写变体）。后台仅投影是否配置、类型、官方域名和节点名称/顺序/成功时间/失败天数，秘密输入留空保留，明确清除或更换来源时删除节点状态。没有数据库结构变更。
- 用户 AG 账号保存 `proxy_mode=platform/custom`；自有代理仅接受公网 HTTP/SOCKS5，与 AnyRouter 的选择方式一致。AnyRouter 现有代理池保持原行为。未配置平台来源明确失败，不使用原 AG 环境变量、默认直连或公开免费列表。
- [AgentRouterConnection](../../../../app/service/AgentRouterConnection.php) 先按已成功记录顺序匿名预检，再从站长订阅的旋转游标继续筛选。最多保存三个已完成登录及退出的节点，新记录加入尾部，满额淘汰尾部；已有成功记录不因日期更换而调序。失败首次保留并冷却十分钟，两个不同执行日失败后移除；同日重试不重复计数，恢复成功清零。来源指纹包含官方域名，配置改变不复用旧证明。
- 一个安装级 `TaskExecutionLock` 覆盖平台主管选择、会话和状态写回，后台保存使用同一锁；不持有数据库事务跨网络。登录前可换候选，登录后的网络/WAF/429 标记失败并由统一调度的下一次有界重试切换，当前执行从不重放 POST。凭据错误不惩罚节点，余额读取失败仍保留已确认的签到。
- [AgentRouterSubscription](../../../../app/service/AgentRouterSubscription.php) 使用锁定 Symfony YAML 6.4 安全解析 Clash、JSON 与普通/Base64 节点 URI，最多 1 MiB、200 个节点，每个节点最多 8 KiB。只保留协议白名单和受限传输字段，丢弃订阅规则、监听、远程提供器、脚本及本地文件路径。公共订阅与节点解析并固定 DNS 地址，TLS/SNI 和 WebSocket Host 保留，禁随重定向；只允许明确后台常规代理使用内网地址。
- [AgentRouterRelay](../../../../app/service/AgentRouterRelay.php) 对加密节点使用镜像固定 digest 的 Mihomo，单节点配置、随机端口/认证、回环监听、静默日志、关闭控制接口与内置 DNS。每次完成、失败或放弃关闭进程与私有文件；`timeout` 将进程生命周期限制为 120 秒，后续执行清理过期目录。没有新增 Compose 服务、公开端口或 Web Docker 操作，不依赖独立个人代理服务或两个旧环境变量。
- 登录/余额/退出协议仍遵守[登录签到决策](2026-11-16-agentrouter-login-checkin.md)。页面只展示缓存资料，注册入口使用明确指定的 AFF 链接。源与代理认证不进入代码、镜像、用户响应或异常文案。

## Alternatives considered

- 个人中心配置全站代理：站长出口的所有权与个人资料无关，不能让普通账号覆盖平台配置；保留账号自有代理选择满足个人出口需求。
- 全站环境固定出口及独立个人容器：缺少后台管理与节点复用，容易跨部署复制私人配置；由私有 DB 设置和短期运行时替代。
- AG 使用 AnyRouter 的公共免费池：违背站长提供来源的要求，公共池证明与失效策略也不同。
- 每天随机节点或首次失败立即删除：浪费已成功记录；与用户给出的第二天保留 A、第三天再试 A 的例子不一致。
- 在同一次登录 429 后切换并重发：登录就是签到，不能确认第一次是否已落地，违反单次 POST 约束；换出口发生在下一次有界执行。
- 将整份订阅交给引擎或持久运行全功能代理：订阅可以定义监听、远程资源和文件路径；限定节点、单个私有短期进程更符合 AG 的边界。
- SQLite 或新代理数据库：既有 `configs` 的事务与文本字段足够保存三个有界节点，保持 MySQL 部署和现有升级路径。

## Consequences

- 新增平台设置、节点三天顺序/同日重试/容量、订阅安全转换和 Linux 真实代理生命周期回归；HTTP 与前端交互覆盖后台权限、保存字段、空值保留、秘密遮蔽与 PJAX。
- 镜像携带额外固定代理二进制，只有平台代理订阅运行时启动，安装级池锁将并发限制为一个。后台改配置需在该池空闲时保存。
- 普通 PHP 部署仍支持常规平台代理与账号自有代理，订阅转换需要包含运行组件的 Linux Docker 镜像。
