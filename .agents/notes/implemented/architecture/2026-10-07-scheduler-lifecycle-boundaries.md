# Agent Note: 调度执行锁、任务启停与跨日边界

Status: implemented

## Problem

`nextExecute` 同时表示计划和 30 分钟执行租约，补挂直接改写它会让另一入口重复领取。任务恢复仅修改开关，遗留的零计划使任务一直不执行。会员到期按账号停掉全部任务，后台编辑又只按任务名更新，分别误伤普通任务和其他平台。午夜随机延迟跨日后再取“明天”，会把每日任务变成隔日任务。生产 MySQL 还记录了两个调度 worker 同时更新退役任务时的死锁。

## Decision

- `Jobs::claimDueJob()` 保留数据库比较并交换租约，同时持有 `TaskExecutionLock`，所有执行入口在 `finally` 释放。锁目录默认使用安装根目录的 `runtime/task-locks`，不使用会随 cron/index 应用变化的 `runtime_path()`。测试以 `app.task_lock_directory` 指向独立临时目录。
- 补挂和任务开关取得相同任务锁才可写入。运行中的任务不接受重复补挂；完成或重试通过 `updateClaimedJob()` 比较自己的租约，不能覆盖用户后来保存的时间或取消状态。锁文件不删除，避免其他进程锁到不同 inode。
- 重新启用零计划任务时按有效挂机时间补齐下一次计划。会员到期按平台、账号及任务的 `vip` 定义停用，普通任务继续执行；后台更新同名任务同时限制平台。
- 随机延迟跨午夜时根据前一计划日的稳定偏移恢复逻辑日期，再计算下一时隙；保留普通首次配置从明天开始的行为。
- 全局退役清理由一个共享维护锁串行处理，最多读取 500 条需要修改的任务，按主键逐条更新并有限重试。维护失败记录不含凭据的诊断并留待后续批次，不能中断正常任务选择；任务白名单仍独立拒绝退役项。
- 网易云成长值流程分别验证奖励列表、领取响应和领取后核验，接口失败不等于空奖励；失败原因进入结果数据，未确认到账不报告成功，也不承诺尚未实现的自动重试。

## Alternatives considered

**只比较 `nextExecute`。** 用户补挂会改写该字段，原来的数据库条件随之失效；只给统一入口加锁也不能覆盖旧监控和 CLI。

**新增租约列和线上 DDL。** 可以用于多节点部署，但当前单安装共享运行卷已有文件锁基础。此次通过公共锁目录和条件写回修复竞争，避免把在线表结构迁移带进修复。

**清理死锁后终止本轮。** 退役项已由执行白名单排除，维护失败没有理由拖延其他平台任务。

**奖励列表异常按零奖励继续。** 无法区分接口不可用与真实空列表，会产生成功误报。

## Consequences

无需修改数据库结构或 Compose 配置。跨入口互斥要求同一安装共享锁目录；未来多节点分散运行卷时须先改成共享锁或数据库独立租约。`SchedulerReliabilityTest.php` 覆盖跨进程锁、租约写回、任务恢复、VIP/平台范围、30 天跨日计划和维护异常；`NeteaseVipRewardTest.php` 覆盖奖励读取、领取及到账核验的成功与失败分支。
